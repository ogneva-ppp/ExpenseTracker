# ExpenseTracker — домашнее задание, лекция № 6

Приложение на **Python + Kivy**, основанное на примере ExpenseTracker из лекции. Реализованы **все три пункта задания**: графики Kivy Garden/Matplotlib, синхронизация с Firebase Realtime Database через REST API, доходы и баланс. Дополнительно: поиск, редактирование, удаление, CSV.

## 1. Запуск на компьютере

Установите Python 3.10–3.12 (рекомендуется 3.11) и откройте терминал в папке проекта.

**Windows:**

```powershell
py -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python main.py
```

**Linux/macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python main.py
```

При проблемах с Kivy проверьте версию Python и инструкции установки на https://kivy.org/doc/stable/gettingstarted/installation.html. На Linux могут потребоваться системные библиотеки для графики. Для графиков используется `kivy_garden.matplotlib.backend_kivyagg.FigureCanvasKivyAgg`.

## 2. Проверка локальных функций

1. «Добавить» → «Доход» → «Продажи» → описание «Заказ» → сумма 15000 → «Сохранить».
2. «Добавить» → «Расход» → «Маркетинг» → описание «Реклама» → сумма 2500 → «Сохранить».
3. На главном экране: доходы 15000, расходы 2500, **баланс 12500 руб.**
4. Нажмите «Графики»: круговая диаграмма расходов и столбчатая по месяцам.
5. Проверьте поиск, изменение и удаление записи, кнопку «CSV».

Данные хранятся в `transactions.json` в каталоге пользовательских данных Kivy (`App.user_data_dir`), а не обязательно рядом с main.py. CSV экспортируется туда же. Формат даты — `ГГГГ-ММ-ДД`.

## 3. Настройка Firebase (обязательна для реальной облачной синхронизации)

Внешний Firebase-проект нельзя создать автоматически из исходного кода; настройте его самостоятельно.

1. Откройте https://console.firebase.google.com/ и создайте проект.
2. В **Build → Authentication → Sign-in method** включите **Email/Password**. В **Users** создайте тестового пользователя с email и паролем.
3. В **Build → Realtime Database** создайте базу. Скопируйте её **Database URL** вида `https://имя-default-rtdb.europe-west1.firebasedatabase.app` (регион может отличаться). Используйте **Realtime Database**, не Firestore.
4. В разделе **Realtime Database → Rules** вставьте содержимое `firebase.rules.json` и опубликуйте правила. Они ограничивают доступ каждому пользователю только его данными `/users/UID`.
5. В **Project settings → General** найдите **Web API Key** (при необходимости зарегистрируйте веб-приложение, чтобы увидеть конфигурацию). Это не секретный серверный ключ. Не используйте service account/private key в приложении.
6. В программе нажмите **Облако**. Введите Database URL, Web API Key, email и пароль тестового пользователя. Нажмите **1. Войти**.
7. Нажмите **2. Отправить локальные данные в облако**. После успешного сообщения проверьте путь `users/<uid>/transactions` в консоли Firebase.
8. Для проверки обратной загрузки запустите программу на другом компьютере с тем же Firebase-пользователем или измените локальные данные и нажмите **3. Скачать из облака**.

**Важно:** это демонстрационная *ручная* синхронизация по кнопке, а не автоматическая фоновая. Выгрузка **полностью заменяет облачный список**, загрузка **полностью заменяет локальный список**. Перед загрузкой создаётся локальная резервная копия `transactions_before_cloud.json`. Не редактируйте одновременно на двух устройствах: автоматического разрешения конфликтов нет. Для реального многопользовательского продукта потребуются обновление просроченного токена, безопасная политика конфликтов, постраничная загрузка и более строгая валидация на сервере. Вход действует до истечения Firebase ID token (обычно около часа); при ошибке авторизации войдите заново.

**Безопасность:** не выбирайте открытые правила тестового режима для реальных финансовых данных; используйте `firebase.rules.json`. Пароль не сохраняется в локальный файл, а отправляется напрямую по HTTPS в Firebase Authentication. Для демонстрации используйте вымышленные данные.
